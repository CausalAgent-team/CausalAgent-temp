# P2-M 真实验收报告

## 文档职责

记录 P2-M 真实验收范围、实际命令、失败原因和证据边界；本报告不把 fake authority、unit test 或本地文件 runner 结果写成 MySQL/生产部署通过。

## 适用范围

适用于本次 `feat(mcp)/causal-mcp-v2` 的 P2-M 隔离验收脚本、临时容器和结果记录；不代表 P3 worker 接入或 P5 全链路生产验收。

## 执行边界

- 工作区：`feat(mcp)/causal-mcp-v2`，执行前已有未提交的 P2-M 实现和文档改动，未回退、覆盖、提交或推送。
- 允许写入：本目录下的验收脚本和报告。
- 真实算法输入：`tests/sachs.csv`；它是本地 fixture 文件，不是 MySQL Job/file authority。
- 容器环境：复用已有 `causalagent-demopaper-unit-test:latest`，不启动应用生产服务，不创建业务数据库卷。
- 机密边界：报告不记录密码、token、连接串、CSV 正文或完整异常正文。

## 脚本复现

```powershell
docker compose -f docker-compose.test.yml run --rm unit-test python tests/acceptance/p2_mcp/run_acceptance.py
```

脚本位置：[`run_acceptance.py`](run_acceptance.py)。它只打印结构化汇总，不落盘用户数据；MySQL 和容器日志项会显式输出 `NOT_RUN`，不会伪造通过。

## 残余风险与下一步

1. 当前 MySQL 证据是最小隔离 schema fixture；仍需在完整 migration/Compose primary 中复跑并记录 source role。
2. OLC 已在小型连续 fixture 真实通过；Sachs 11 节点长跑未作为验收样本，生产数据规模仍需单独基准。
3. 当前 RSS/CPU 是 `2 CPU/2 GiB` 容器和固定 fixture 基线，不等同于生产容量承诺。
4. transport 故障注入已转换为 `MCP_TRANSPORT_FAILED` 并抑制预期 teardown traceback；真实容器日志扫描已覆盖一次 PC 调用，未知异常仍需在正式部署采集链路中继续观察。
